# 修改与实验记录规范

本目录保存项目修改方案及对应实验记录。新增记录统一遵循以下命名与内容格式。

## 文件命名

```text
YYYY-MM-DD-NN-主题.md
```

- **日期**：本次修改的记录日期，使用 `YYYY-MM-DD` 格式。
- **次序**：当天第几次独立修改，从 `01` 开始递增，不足两位补零。创建文件前检查目录中当天已有编号，取最大编号加一；编号不按主题分别计数，也不因删除文件而重新使用。
- **主题**：简短说明修改内容，使用中文或小写英文；英文单词之间使用 `-`，不使用空格。

示例：

```text
2026-11-09-01-page-aware-tool-filtering.md
2026-11-09-02-open-product-button-validation.md
2026-11-10-01-selection-summary.md
```

同一次修改的实验结果继续补充到原文件，不另占编号、不因实验完成日期变化而重命名。独立的新修改使用新编号，并引用相关前序记录。历史文件不因本规范自动重命名；`README.md` 不参与编号。

## 内容格式

正文固定按以下顺序组织，保留全部五个章节：

**要解决的问题 → 希望达到的目的 → 解决方案 → 实验验证结果 → 实验结果分析（是否达到目的）**

可直接复制以下模板：

```markdown
# YYYY-MM-DD-NN：主题

## 1. 要解决的问题

- 说明当前行为、复现条件及影响。
- 给出依据，例如轨迹 task_id、错误类型、出现次数或相关代码位置。

## 2. 希望达到的目的

- 明确预期行为和可验证的验收指标。
- 说明需要关注的回退指标，例如严格成功率、错误购买和无终局数量。

## 3. 解决方案

- 说明实现方式、涉及文件与关键逻辑。
- 写清本次修改范围，以及相关前序记录或对照版本。
- 区分已实现内容与尚未实施的方案。

## 4. 实验验证结果

- 状态：待验证 / 验证中 / 已完成 / 执行受阻。
- 验证配置：基线与实验运行名称、题集及数量、模型、主要参数和代码版本。
- 验证方式：实际执行的测试或评测命令、通过数、失败项或阻碍。
- 结果位置：轨迹、汇总、报告及相关产物路径。

| 指标 | 修改前 | 修改后 | 变化 |
| --- | ---: | ---: | ---: |
| 目标问题出现次数 | 待验证 | 待验证 | 待验证 |
| 严格成功率 | 待验证 | 待验证 | 待验证 |
| 未完成 / 无终局数量 | 待验证 | 待验证 | 待验证 |

## 5. 实验结果分析（是否达到目的）

- 结论：达到 / 部分达到 / 未达到 / 暂无法判断。
- 将结果逐项对应到第 2 节的目的，说明依据、改善与不足。
- 说明对照是否一致、其他改动或服务差异是否影响归因。
- 给出后续处理建议。
```

## 填写要求

- 未运行实验时，第 4 节写明“待验证”及原因，第 5 节写“暂无法判断”，不得将测试通过等同于模型效果提升。
- 保留失败和受阻事实；基础设施错误与模型行为失败分开记录。
- 对比需使用一致题集并说明配置差异；不满足单变量条件时，不将变化全部归因于本次修改。
- 若一次修改有多轮实验，在第 4、5 节内按实验名称和实际日期分小节，保留原有结果。
- 不写入密码、密钥或令牌；引用既有记录和实验产物时优先使用相对路径。
