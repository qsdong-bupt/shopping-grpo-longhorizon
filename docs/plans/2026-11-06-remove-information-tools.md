# 移除四个信息页动作：设计与实现记录

日期：2026-11-06。用户授权：移除四个动作及 observation 中的对应按钮，记录改动并提交到 GitHub `V2.0`。

## 目标与证据

移除 `view_description`、`view_reviews`、`view_attributes`、`view_features`，模型只能通过搜索结果页、商品详情页完成核验与购买。

对当前 23,421 条源商品的检查结果：

- `full_description` 全部等于商品标题，没有独立描述证据。
- loader 的评论来自空的 `all_reviews`，运行时 `Reviews` 为空。
- `small_description` 全部缺失，不能提供有效特点信息。
- 263 件商品的属性超过 10 条，其中 19 件来自源 `tag=eval`。旧详情摘要只显示前 10 条；因此删除属性页必须同时把详情改为完整属性。

此结论只适用于当前冻结商品数据。未来若引入独立描述、真实评论或新特点，应重新设计公开证据字段与版本，不能依赖被删除的页面。

## 交互与观测变化

工具从 12 个收敛为 8 个：`search_products`、`open_product`、`select_option`、`next_page`、`prev_page`、`back_to_search`、`buy_now`、`finish_without_purchase`。

1. Python 唯一工具定义及 `configs/tools.json` 同步删除四个 schema 和动作映射，清理未公开的旧 `think` 配置。
2. Student / Teacher 提示词不再教授信息子页。Teacher 明确商品详情直接提供完整属性。
3. 删除四个 HTML 子页模板、Flask 子页路由、SimServer 导航分支，以及相应状态与访问记录；详情 HTML 不再生成四个按钮。
4. 搜索摘要仍展示前 10 条属性，商品详情、选择规格后的详情均展示全部属性。商品标题、品牌、品类、价格、规格轴与选择状态继续保留。
5. 动作守卫拒绝旧工具名；旧按钮名仍仅作为内部保留导航词，防止被伪装为 `select_option` 参数，不进入模型工具 schema。
6. 结构化渲染器拒绝包含旧按钮的状态；投影器拒绝旧版 observation 或旧按钮 footer。结构化详情超出 token 预算时显式报错，要求调整详情预算，不静默截断购买证据。

## Reward、终止与评测

环境 Reward v3 购买比较逻辑不变：购买时根据 session ASIN 从后端商品字典读取完整记录，使用实际已选规格和价格判分，不要求先访问信息子页。

正式严格成功仍要求完整 `gold_purchase` 终局且 `reward_valid=true`；替代购买不会变成正式严格成功。SFT 的 Gold / 冻结 JEV 替代购买准入规则保持原样，额外增加交互协议校验。

配套变化：

- 删除信息页访问次数指标及其消费者；确定性指标版本升级为 `shopping-deterministic-metrics-v2`。
- 删除信息页的进度信用，不再通过首次访问子页刷新无进展计数；保留 35 步上限、连续无进展 4 步、精确动作重复 2 次的边界。终止追踪版本升级为 v4。
- GRPO 适配层原有的“访问信息页 +1 分”被移除。探索充分度现在为 0–2：打开至少两个不同候选 +1，至少两组不同搜索参数 +1；充分阈值仍为 2。因此必须同时满足两项才能进入尽力买错档。`-0.45 / -1.00` 档位数值保持原样。这是训练塑形条件变化，不是环境 Reward v3 的商品判分变化。
- 两个轨迹分析脚本的探索工具集合同步清理。

## 2026-11-07：移除信息页前后 200 题对照实验

### 数据来源、口径与可比性

用户指定以下报告分别代表本次改动前、后的实验：

- 改动前：`outputs/evaluation/qwen35_4b_smoke/report_200.html`。
- 改动后：`outputs/evaluation/qwen35_4b_check_20261107/report.html`。

本记录直接解析两份 HTML 的 `REPORT_DATA`，依据各自内嵌的 200 条完整轨迹、结果分类和工具调用统计进行配对分析，不用目录名推断样本范围。两组均为 200 个唯一 task_id，集合完全一致；逐题用户需求全部相同，带画像题目的画像文本也一致。旧目录的 summary.json 核对后与旧报告的主要计数一致，但分析以指定 HTML 快照为准，不混入后续 1092 题完整运行。

两组属于 Qwen3.5-4B 的协议改动前后对照，不是 SFT/GRPO 权重训练收益实验。旧轨迹没有 runtime_protocol，新轨迹记录 Environment v2.2 / observation v3 / tool schema v3。系统提示随动作空间更新；本次变更还包含完整详情属性展示、信息页进度信用移除及终止追踪 v4，因此不能把差异单独归因于“少了四个工具”。

两份报告 meta 中 max_steps、max_tokens、temperature 等字段为空，不能仅凭报告确认全部推理配置和模型权重指纹完全一致。新运行的配置另保存在 run_identity.json；旧运行缺少同等身份记录。耗时也受到运行负载、服务预热等因素影响。本实验是同题单次对照，没有多次重复或随机种子方差估计，不据净增加 1 道成功题宣称统计显著提升。

严格成功沿用完整 gold_purchase 且 reward_valid=true 的定义；终局完成包括错误购买、循环终止等失败终局，不等同于任务成功。buy_now 调用数是购买动作数，不能直接当成成功购买数。

按全部动作尝试计算（已执行动作 + 守卫拒绝），拒绝占比从 210/2312=9.1% 变为 171/1123=15.2%。因此必须同时报告“受影响题目减少”和“剩余动作中的拒绝比例仍高”，不能只凭拒绝总数下降就认定协议掌握程度全面改善。

### 不足一：页面导航和规格参数错误仍是无终局的主要来源

改动后的 29 条无终局轨迹全部为 invalid_action_limit，最后连续 3 次动作被本地守卫拒绝；其拒绝原因均为 click_not_in_previous_observation，而非服务连接故障或 35 步耗尽。

| 最终失败模式 | 数量 | 证据与解释 |
|---|---:|---|
| 详情页直接打开其他商品或调用下一页 | 20 | 当前详情没有对应候选链接或翻页按钮，模型未先返回 |
| 返回搜索首页后继续翻页 | 6 | back_to_search 返回 search_home，不是原搜索结果页 |
| 返回搜索首页后仍选择旧商品规格 | 1 | task 179 使用历史详情页规格 |
| 详情页规格文本不匹配 | 2 | task 76 拼接了不同选项的文字；task 959 遗漏规格内部空格 |

以 task 76 为例，真实“单风扇散热”选项没有“铝壳”二字，模型却组合成含“铝壳”的新字符串，并连续原样重试三次。task 959 则是规格空格不一致。二者属于参数匹配问题，与页面导航错误应分开处理。

本次新轨迹完全没有执行 prev_page，不能只把它解释为省掉返回开销；结合 20 条详情页非法打开/翻页轨迹，也暴露出模型没有掌握详情页返回搜索结果的路径。实际工具名是 prev_page，而不是 previous_page。后续可在协议提示与按页面生成的拒绝反馈中明确返回工具和前置条件，返回后必须重新读取 observation，再决定打开商品、翻页或搜索；不应替模型自动执行“返回 + 打开商品”。

### 不足二：循环同时包含模型行为问题与环境链路问题

改动后 12 条 repeat_loop 分解如下。它们有环境终局，与上述 29 条“无终局”不是同一类别。

| 原因 | 数量 | task_id |
|---|---:|---|
| 规格已选中，仍连续重复选择同一规格 | 7 | 753、528、1229、1178、560、1409、162 |
| 按钮显示文本与实际规格空格不一致，选择无效后反复重试 | 2 | 780、1211 |
| 重复搜索、重开旧商品、重选旧规格，连续没有新增证据 | 2 | 728、733 |
| 连续有效翻页被精确动作重复规则终止 | 1 | 1449 |

- 7 条已选规格循环中，selected_options 已显示选中值，模型仍重复选择，没有转向购买、其他必要规格或返回。这是状态读取与下一步决策衔接不足；轨迹不足以确定模型内部动机。
- task 780：available_options 的真实值是“psv2000硅胶套  黑色”（两个空格），按钮 footer 是“psv2000硅胶套 黑色”（一个空格）。模型按 footer 调用可通过守卫，但环境 selected_options 始终为空。task 1211 的“中性110  一白”与“中性110 一白”同样不一致。这两条不能全归咎于模型，应修复显示、守卫与环境执行之间的规格标识一致性。
- task 728、733 在已看过的搜索和候选之间往返，连续 4 个执行动作没有新增运行证据而终止。两条均未发生上下文压缩，没有证据将循环归因于历史压缩丢失。
- task 1449 连续三次 next_page，每次均新增 20 个商品，no_progress_steps 始终为 0，却因相同动作签名重复达到阈值被终止。当前“精确重复”只看动作名和参数，未区分页码变化。至少此例不宜当作无效探索，应以页面/结果集是否变化辅助判定，而不是简单放宽全部重复阈值。

这三条环境链路或判定相关样本暂保留原报告分类，不在本次文档分析中追改历史指标；修复后的效果需要另开运行验证。

### 结论与后续验证

### 重复选择的改善与边界

原有 10 条“成功选中后反复选择”中，8 条不再因该类循环结束：task 363 转为严格成功；728、1003、1428、1452、1124 转为部分满足购买；1409 转为主动放弃；1178 继续浏览后转为翻页循环。1285 与 753 仍重复选择。也就是说，原 10 条中仅 1 条因此观察到严格成功，不能把解除重复直接等同为满足需求。

- 已选规格仍被连续选择：1285、753、179，共 3 条。1285 仍缺“套餐”维度，753 两个维度均已选择，179 只有一个维度；因此问题仍非单纯由多规格造成。轨迹确认模型收到“已选中、重复不改变状态”的反馈后，依然提交相同调用，说明提示不能保证下一步决策。
- 选择没有生效：148，共 1 条。连续调用后 selected_options 仍为空，反馈已明确“未确认成功”，模型依旧重试。应继续核查原始选项标识与空格映射，不能用提示替代环境标识修复。
- 有效翻页被循环规则停止：1449、1315、733、1178，共 4 条。末次翻页均发现 10 或 20 个新 ASIN，no_progress_steps=0；当前重复动作签名规则仍会终止它们。此次未改该规则。

### 结论与后续方案

本次反馈干预对减少连续重复选规格有效，整体 repeat_loop 明显减少，并伴随严格成功与平均奖励提高；但未降低无终局和守卫拒绝，购买行为中仍有大量部分满足需求。反馈解决的是状态理解和继续决策的一部分，尚不能替代商品约束判断。

后续建议分开验证三项：第一，以当前真实状态识别并反馈“同商品同规格已选中”的无效重复，评估是否需要在守卫层阻止无状态变化的重复；若加入阻止策略，需保留更换同轴值及其他维度选择，并避免把重复转移为 invalid_action_limit。第二，修复原始选项标识与展示字符串映射，保证反馈中的“选择成功”与实际环境状态一致。第三，修改循环终止判据，让有新增商品/证据的有效翻页继续执行，并用无进展状态约束真正循环。以上均未混入本次实验，需各自用相同题集回归。
